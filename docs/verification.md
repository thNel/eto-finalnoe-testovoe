# Проверка сценариев

## Проверки из чистого клона

Выполните установку из [README](../README.md) с пустой локальной БД. Затем проверьте миграции и тесты из каталога `backend/`:

```powershell
.\.venv\Scripts\python.exe -m alembic current
.\.venv\Scripts\python.exe -m alembic check
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Для Linux и macOS используется `.venv/bin/python`. Во фронтенде выполните `npm ci` и `npm run build`.

Тесты бэкенда используют подставной Keitaro. Тесты редактора создают временную SQLite, а тесты подписок управляют результатами опроса для нескольких клиентов. Для них достаточно установленных зависимостей.

| Набор | Покрытие |
|---|---|
| `test_campaigns.py` | Порядок сборки кампании, обязательная проверка перед включением, ошибки потока, неправильный GEO и сверка после таймаута включения |
| `test_editor.py` | Сохранение черновика, версии, перерасчёт долей, закрепление, удаление последнего оффера, история, возврат, внешние правки и частичная публикация |
| `test_campaign_events.py` | Общий цикл для одинаковых ID, независимость разных кампаний, рассылка изменений, повтор опроса при сбое и остановка после отключения |

## Создание кампании

1. Откройте главную страницу и убедитесь, что список отобразился.
2. Нажмите «Новая кампания». Для общей тестовой среды укажите имя вида `test_фамилия_campaign1`, например `test_gusev_campaign1`.
3. Введите `PL, AU`. Найдите активный оффер по названию или ID и выберите его из списка.
4. Отправьте форму. После успеха появятся ссылка кампании, ссылка на админку Keitaro и переход в редактор.
5. Откройте кампанию в Keitaro. Сверьте домен, группу и источник. Проверьте, что поток Google принимает оба указанных GEO, а поток с оффером принимает остальной трафик и содержит выбранный оффер с долей `100%`.
6. Для проверки валидации введите неподдерживаемый код `ZZ`. Форма покажет ошибку GEO, а FastAPI отклонит ввод до запроса на создание кампании в Keitaro.

## Черновик, отмена и публикация

1. Откройте редактор своей тестовой кампании и найдите поток с офферами.
2. Удалите единственный оффер. Проверьте, что он по-прежнему имеет `100%` в колонке Keitaro и `0%` в черновике.
3. Перезагрузите страницу или откройте ссылку редактора в другом окне. Должны сохраниться отметка черновика и новое значение.
4. Отмените изменения. Оффер должен вернуться к опубликованному состоянию с `100%`.
5. Снова удалите оффер и опубликуйте изменения. Проверьте в Keitaro, что список потока пуст. В редакторе оффер должен быть в истории с `0%` и кнопкой «Вернуть».
6. Верните оффер. Доля `100%` появится в черновике. Опубликуйте и проверьте её в Keitaro.
7. Если в каталоге доступны четыре активных оффера, добавьте четвёртый к трём незакреплённым. Доли должны стать `25/25/25/25`. Закрепите одну долю на `40%`, нажав Enter после редактирования, и проверьте, что остальные получили `20%` каждая.

Сценарий с несколькими офферами можно проверить тестами редактора, если тестовый ключ видит только один оффер.

## Внешние изменения и WebSocket

1. Создайте черновик и откройте в двух вкладках один и тот же редактор.
2. В Keitaro измените только свою тестовую кампанию. Например, измените её название, сохранив тестовый префикс. При наличии второго активного оффера можно добавить его напрямую в редактируемый поток.
3. Дождитесь очередной проверки. В обеих вкладках должно появиться предупреждение. Черновик должен сохраниться.
4. Выберите «Продолжить редактирование», чтобы закрыть окно. При нажатии «Опубликовать» приложение запросит подтверждение перезаписи.
5. Если дополнительный оффер появился только в Keitaro, после подтверждённой публикации он должен появиться в локальной истории с `0%` и кнопкой «Вернуть».
6. Временно оборвите WebSocket. После восстановления соединения редактор перечитает кампанию через REST.

У каждого открытого окна своё соединение. Один цикл опроса Keitaro используется всеми окнами конкретной кампании. Разные кампании опрашиваются независимо. Это отдельно проверяется тестами подписок.
