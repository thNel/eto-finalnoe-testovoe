# Веб-платформа для управления кампаниями Keitaro

Приложение создаёт кампании по заданному шаблону и позволяет редактировать распределение трафика между офферами в существующих кампаниях. Keitaro определяет, какая конфигурация реально работает. Приложение хранит черновики и историю удалённых офферов, показывает актуальное состояние кампании и публикует изменения по команде пользователя.

## Создание кампании

Пользователь вводит название, указывает GEO и выбирает существующий оффер через поиск по названию или ID. Домен, группа и источник берутся из настроек приложения. В Keitaro создаётся кампания с позиционной ротацией и двумя потоками:

1. Трафик из указанного GEO перенаправляется на Google.
2. Остальной трафик направляется на выбранный оффер.

После создания пользователь получает ссылку на кампанию и может открыть её в редакторе.

## Редактирование кампании

Редактор показывает потоки, офферы, доли трафика и клики за сегодня. В каждом потоке можно добавлять, удалять и возвращать офферы, а также закреплять отдельные доли. Бэкенд распределяет остаток между активными офферами с незакреплёнными долями и округляет результат так, чтобы сумма составляла 100%. Последний оффер тоже можно удалить и опубликовать поток без офферов.

Любая правка автоматически создаёт или обновляет серверный черновик кампании. При открытии кампании с другого устройства редактор показывает тот же черновик с отметкой «Не опубликовано». Кнопка «Опубликовать» применяет изменения в Keitaro, а «Отменить изменения» удаляет черновик. После успешной публикации приложение закрывает черновик, перечитывает кампанию из Keitaro и показывает сохранённое состояние.

Офферы, удалённые при публикации, остаются в локальной истории конкретного потока с долей 0% и кнопкой «Вернуть». Возврат создаёт правку в черновике и запускает перерасчёт долей.

## Синхронизация с Keitaro

Сервер периодически сверяет открытые кампании с Keitaro. При изменении конфигурации он уведомляет клиентов по WebSocket. Фронтенд перечитывает кампанию через REST, в том числе после переподключения WebSocket.

Если конфигурация изменилась при наличии черновика, приложение сохраняет черновик и показывает предупреждение со ссылкой на Keitaro. Перед публикацией сервер повторно сверяет состояние. Перезапись изменившихся списков офферов и долей в редактируемых потоках требует явного подтверждения. Если после подтверждения конфигурация снова изменилась, пользователь увидит предупреждение повторно.

Если в Keitaro после начала редактирования добавили оффер, которого нет в черновике, редактор покажет, что он будет удалён при публикации. Пользователь может добавить его в черновик. Если публикация уберёт оффер из потока, он попадёт в локальную историю и станет доступен для возврата.

## Стек

- Бэкенд — FastAPI, SQLAlchemy, Alembic и SQLite.
- Фронтенд — React, TypeScript и Mantine.
- Чтение и изменение данных идут через REST API. Один запрос чтения кампании возвращает опубликованное состояние, черновик и признак внешних изменений.
- WebSocket доставляет уведомления об обновлениях. Ключ Keitaro хранится на сервере.
