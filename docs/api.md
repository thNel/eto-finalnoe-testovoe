# REST и WebSocket

В разработке браузер обращается к Vite на порту `5173`. Запросы `/api` проксируются в FastAPI на порт `8000`. Swagger приложения доступен на [локальном FastAPI](http://127.0.0.1:8000/docs). JSON-запросы принимают `Content-Type: application/json`. Ключ Keitaro FastAPI добавляет в собственные исходящие запросы к трекеру.

## Маршруты

| Метод и путь | Ответ | Назначение |
|---|---|---|
| `GET /api/v1/health` | `200`, `{"status":"ok"}` | Проверить подключение SQLAlchemy к БД |
| `GET /api/v1/campaigns` | `200`, страница кампаний | Получить кампании, доступные ключу Keitaro |
| `GET /api/v1/offers` | `200`, массив офферов | Найти активные офферы по названию или ID |
| `POST /api/v1/campaigns` | `201`, активированная кампания | Создать кампанию с двумя потоками |
| `GET /api/v1/campaigns/{id}` | `200`, состояние редактора | Прочитать опубликованную конфигурацию и черновик одним запросом |
| `PATCH /api/v1/campaigns/{id}/draft` | `200`, обновлённое состояние редактора | Применить одно действие в черновике |
| `DELETE /api/v1/campaigns/{id}/draft?version={version}` | `200`, состояние после отмены | Удалить черновик |
| `POST /api/v1/campaigns/{id}/publications` | `200`, состояние после публикации | Применить к Keitaro подтверждённый черновик |
| `WS /api/v1/campaigns/{id}/events` | События JSON | Подписаться на изменения версии Keitaro |

## Список кампаний и поиск офферов

`GET /api/v1/campaigns?offset=0&limit=25` принимает смещение от `0` и лимит от `1` до `100`. Значения по умолчанию — `0` и `25`. Ответ содержит `items` с записями `{id, name, state, admin_url}` и `has_more`. FastAPI запрашивает у Keitaro одну дополнительную запись, чтобы определить, есть ли следующая страница.

`GET /api/v1/offers?q=18813` возвращает до 30 записей `{id, name}`. Параметр `q` необязателен, длина до 200 символов. Поиск регистронезависимый, по подстроке названия или ID. Точное совпадение по ID ставится первым. В выборку входят активные офферы.

## Создание кампании

`POST /api/v1/campaigns`

```json
{
  "name": "test_gusev_campaign1",
  "geo": ["PL", "AU"],
  "offer_id": 18813
}
```

Название после удаления крайних пробелов должно содержать 1–200 символов. `geo` — непустой массив двухбуквенных кодов ISO. Интерфейс преобразует ввод через пробел или запятую в этот массив. `offer_id` — положительное целое число, соответствующее активному офферу Keitaro. Домен, группа и источник определяются на сервере.

Ответ `201` содержит поля `id`, `name`, `state`, `admin_url` и `tracking_url`. Поле `state` равно `active` после подтверждённого включения. `admin_url` открывает карточку кампании в Keitaro. `tracking_url` содержит адрес домена и алиас или равен `null` на учебном стенде без трекинга.

При сбое создания `detail` может содержать `step`, `campaign_id`, `campaign_state`, `alias`, `admin_url` и `upstream_status`. Набор полей зависит от того, что Keitaro успел подтвердить.

| Значение `step` | Этап |
|---|---|
| `validate` | Проверка оффера и поиск домена, группы и источника |
| `campaign` | Создание отключённой кампании |
| `geo_stream` | Создание потока с GEO |
| `offer_stream` | Создание потока с оффером |
| `verify` | Повторное чтение конфигурации из Keitaro |
| `enable` | Включение кампании |

Если пришёл `campaign_id` со статусом `disabled`, по ссылке из ответа доступно текущее состояние частично собранной кампании. Значение `unknown` означает, что сервису не удалось подтвердить состояние. Поиск по алиасу помогает проверить результат запроса, завершившегося таймаутом.

## Чтение редактора

`GET /api/v1/campaigns/123` возвращает одну структуру для обоих режимов редактора. Пример для потока, из которого в черновике удалили оффер с текущей долей `100%`.

```json
{
  "campaign": {
    "id": 123,
    "name": "test_gusev_campaign1",
    "state": "active",
    "admin_url": "https://tracker.example/admin/#!/campaigns/123"
  },
  "mode": "draft",
  "version": 4,
  "remote_revision": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "external_changed": false,
  "streams": [
    {
      "id": 20,
      "name": "Поток с офферами",
      "state": "active",
      "editable": true,
      "edited": true,
      "clicks_today": 4,
      "offers": [
        {
          "id": 18813,
          "name": "Тестовый оффер",
          "published_share": 100,
          "share": 0,
          "state": "removed",
          "pinned": false,
          "external_removal": false,
          "removed_in_keitaro": false
        }
      ]
    }
  ]
}
```

| Поле | Значение |
|---|---|
| `mode` | `published` или `draft` |
| `version` | Версия локального состояния. Её передают команды изменения, отмены и публикации |
| `remote_revision` | Версия конфигурации, прочитанной из Keitaro, в виде 64 шестнадцатеричных символов |
| `external_changed` | Текущая версия Keitaro отличается от версии, сохранённой в черновике |
| `editable` / `edited` | Поток принимает правки / для потока есть изменения в открытом черновике |
| `clicks_today` | Клики в потоке за день. `null` означает, что отчёт недоступен или произошла ошибка при его получении |
| `published_share` | Доля в Keitaro. Для оффера из истории удаления возвращается `0`. Для оффера, который добавлен только в черновике, возвращается `null` |
| `share` | Доля, показанная в редакторе с учётом черновика |
| `state` оффера | Состояние назначения. `removed` означает, что редактор показывает удалённый оффер с `0%` |
| `external_removal` | Оффер появился в Keitaro после начала правок этого потока и отсутствует в черновике |
| `removed_in_keitaro` | Оффер удалён из потока в Keitaro и пока включён в черновик |

## Редактирование и отмена

`PATCH /api/v1/campaigns/123/draft` сохраняет одну операцию и возвращает новую версию редактора.

```json
{
  "version": 4,
  "stream_id": 20,
  "offer_id": 18813,
  "operation": "pin",
  "share": 40
}
```

| Операция | Результат |
|---|---|
| `add` | Добавить активный оффер из каталога |
| `remove` | Убрать оффер из текущего списка черновика |
| `restore` | Включить активный оффер из истории или из текущего состояния Keitaro |
| `pin` | Закрепить указанную долю либо сохранить текущую, если поле `share` пропущено |
| `unpin` | Вернуть оффер в автоматическое распределение |

`share` — необязательное целое число от `0` до `100`. Поле используется операцией `pin`. Черновик создаётся при первом успешном изменении. `DELETE /api/v1/campaigns/123/draft?version=4` отбрасывает неопубликованные правки. Сохранённая история и применённые изменения остаются доступны.

## Публикация

Обычный запрос публикует черновик с указанной локальной версией.

```http
POST /api/v1/campaigns/123/publications
Content-Type: application/json

{"version": 4}
```

Если в Keitaro уже другая конфигурация, FastAPI отвечает `409` и передаёт `detail.code: "external_change"` с `detail.remote_revision`. Клиент перечитывает кампанию и открывает окно подтверждения. При явном подтверждении он передаёт `confirm_revision` для показанной версии. Сервер повторяет сверку перед записью каждого потока. При успехе возвращается обновлённое состояние редактора в режиме `published`.

Публикация нескольких потоков выполняется последовательно. Если один из потоков не удалось подтвердить, `detail.code: "publication_failed"` содержит его `stream_id`. Последующий GET показывает успешно применённые изменения и оставшуюся часть черновика.

## Ошибки

Ошибки операций имеют формат `{"detail":{"message":"…","code":"…"}}`. `code` присутствует у ошибок редактора. Валидация FastAPI возвращает массив `detail` с путём поля и описанием ошибки.

| Статус | Когда возвращается |
|---|---|
| `404` | Кампания не найдена в Keitaro |
| `409` | Устарела локальная версия черновика, изменился Keitaro, поток уже недоступен или возникло противоречие с текущим состоянием оффера |
| `422` | Некорректный запрос, выбран недоступный или неактивный оффер, закреплённые доли не позволяют распределить 100% |
| `502` | Запрос к Keitaro отклонён, произошла ошибка связи или получен неожиданный ответ |
| `503` | БД недоступна, не задан ключ или серверу не удалось однозначно выбрать настройки кампании |
| `504` | Keitaro не ответил вовремя |

## Событие WebSocket

При подключении к `/api/v1/campaigns/{id}/events` подписчик получает последнюю известную версию. Затем сообщение приходит, если версия изменилась.

```json
{
  "type": "campaign_revision",
  "campaign_id": 123,
  "remote_revision": "bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb"
}
```

Значение `remote_revision: null` сообщает, что кампанию больше не удалось найти по ID. Клиент проверяет состояние обычным GET. При восстановлении соединения фронтенд использует первое событие как сигнал перечитать REST даже при совпавшей версии.

Список кампаний подписывается на `/api/v1/campaigns/events?offset=0&limit=25`. Параметры совпадают с `GET /api/v1/campaigns`. Сервер присылает `{"type":"campaign_list_revision","remote_revision":"…"}` при подключении и при изменении выбранной страницы. После события клиент перечитывает ту же страницу через REST.
